1. WEB-SOCKET СЕРВЕР (server/ws/battle.ts — новый файл):
   - Использовать пакет `ws` (уже в зависимостях? — проверь; если нет, npm i ws).
   - Fastify-плагин: fastify.register(websocketPlugin). 
   - Эндпоинт: ws://localhost:3000/ws/battle/:battleId?lang=ru|en
   - При подключении:
     * Валидация: battleId существует, battle.status === 'active'.
     * Если нет — close(4004, 'battle_not_found') или close(4000, 'battle_finished').
     * Добавить соединение в room Map<battleId, Set<WebSocket>>.
     * Отправить первое сообщение: { type: 'state', state: <BattleState с логом> }.
   - Входящие сообщения от клиента:
     * { type: 'action', action: Action, lang: 'ru'|'en' } →
       - загрузить state, применить applyAction (для player), если action.type === 'end_turn' → затем runEnemyTurn
       - если action даёт ошибку → { type: 'error', error, message }
       - если ok → сохранить в БД (updateBattleState) → broadcast всем в room: { type: 'update', state, logEntries }
       - если battle.status !== 'active' после действия → broadcast { type: 'end', state } и close(1000) всем в room
     * { type: 'ping' } → { type: 'pong' } (keepalive, каждые 30с)
   - При отключении — удалить из room; если room пуст — не закрывать battle (он в БД, можно вернуться).
   - ВАЖНО: один и тот же battleId может иметь несколько соединений (например, при перезагрузке вкладки) — все получают обновления.
   - ВАЖНО: не доверять клиенту. Валидировать action через Zod. Если action.type === 'end_turn' — сервер сам вызывает runEnemyTurn. Клиент не может отправить 'enemy_action'.

2. СИНХРОНИЗАЦИЯ ПОСЛЕ БОЯ (server/game/battle/sync.ts — новый файл):
   - syncAfterBattle(params: {
       db; state: BattleState; items: Item[]; config: BattleConfig;
       levelTable: LevelTable; lang: 'ru'|'en';
     }): { character: Character; rewards: { xp, loot: {itemId, qty}[] }; }
   - Вызывается, когда battle.status !== 'active' (victory | defeat | fled).
   - Для victory:
     * XP = sum(xpForKill за каждого мёртвого моба)
     * character.xp += XP; цикл: пока character.xp >= xpToNextLevel(character.level) → applyLevelUp (5b), character.level++, character.xp -= xpToNextLevel(level), character.hp_current = hpMax (восстановление при levelup).
     * Лут: для каждого мёртвого моба — прокрутить loot.guaranteed (100%) + loot.rare (шанс). Добавить в inventory через inventory-repo.addItem. Если loot.rare шанс — использовать rng (Math.random на сервере).
     * character.hp_current = player.hp (после боя)
     * Патроны: для equipped weapon, если weapon.charges !== undefined → списать разницу (maxCharges - weaponCharges) из inventory (ammoType). Упрощение: в 6a — только списать, если хватает; если не хватает — обнулить charges, лог «патроны кончились».
     * Аптечки: уже списаны в API 5d (useItem). В 6a — не трогать.
   - Для defeat:
     * character.hp_current = 1
     * character.money = floor(character.money × 0.9)
     * character.location_id = world.startLocationId (стартовый город)
     * XP не начисляется, лут не выдаётся.
   - Для fled (abandon или flee):
     * character.hp_current = player.hp (после боя)
     * XP не начисляется, лут не выдаётся.
     * location_id не меняется (игрок остаётся где был).
   - Сохранить character через character-repo.updateCharacter. Сохранить inventory через inventory-repo (addItem для лута, removeItem для патронов).
   - Вернуть { character, rewards }.

3. API (server/api/battle.ts — доработать):
