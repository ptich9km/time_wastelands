ЗАДАЧА ЭТАПА 2 — создание персонажа с 6 статами, HP и ОД. ТОЛЬКО ЭТО. Не делай карту, бой, инвентарь, магазин, WebSocket.

ВАЖНО: игра по мотивам TimeZero, статы — 6 (STR, AGI, INT, END, PER, INTEL). Стартовые значения — ФИКСИРОВАННЫЕ (3/3/3/3/0/0). Игрок НЕ распределяет очки. Авторост при левелапе — этап 9, не сейчас.

1. СХЕМА БД (добавь в server/db/schema.sql, CREATE TABLE IF NOT EXISTS characters):
   id INTEGER PRIMARY KEY CHECK (id = 1)  -- одиночная игра
   name TEXT NOT NULL CHECK (length(name) BETWEEN 2 AND 20)
   level INTEGER NOT NULL DEFAULT 1
   xp INTEGER NOT NULL DEFAULT 0
   str INTEGER NOT NULL DEFAULT 3
   agi INTEGER NOT NULL DEFAULT 3
   int INTEGER NOT NULL DEFAULT 3    -- интуиция (НЕ интеллект!)
   "end" INTEGER NOT NULL DEFAULT 3  -- выносливость, ВСЕГДА в двойных кавычках в SQL
   per INTEGER NOT NULL DEFAULT 0    -- меткость
   intel INTEGER NOT NULL DEFAULT 0  -- интеллект
   hp_current INTEGER NOT NULL
   hp_max INTEGER NOT NULL
   ap_max INTEGER NOT NULL           -- ОД = 15 + 2×"end"
   money INTEGER NOT NULL DEFAULT 50
   location_id TEXT NOT NULL
   created_at TEXT NOT NULL DEFAULT (datetime('now'))
   updated_at TEXT NOT NULL DEFAULT (datetime('now'))
   CHECK (str >= 1 AND str <= 50)
   CHECK (agi >= 1 AND agi <= 50)
   CHECK (int >= 1 AND int <= 50)
   CHECK ("end" >= 1 AND "end" <= 50)
   CHECK (per >= 0 AND per <= 50)
   CHECK (intel >= 0 AND intel <= 50)
   CHECK (hp_current >= 0 AND hp_current <= hp_max)
   CHECK (ap_max >= 15)
   CHECK (money >= 0)

   ВАЖНО: поле "end" — зарезервированное слово в некоторых версиях SQLite, ВСЕГДА экранируй "end" двойными кавычками в SQL.

2. ПРАВИЛА ПЕРСОНАЖА (server/game/entities/character.ts):
   - Стартовые статы ФИКСИРОВАННЫЕ: str=3, agi=3, int=3, end=3, per=0, intel=0.
   - hp_max = 50 + 5 × "end"  → на старте 65.
   - ap_max = 15 + 2 × "end"  → на старте 21.
   - hp_current = hp_max при создании.
   - money = 50.
   - location_id = fastify.gameData.world.startLocationId.
   - Имя: 2–20 символов, /^[\p{L}0-9 \-]{2,20}$/u (буквы, цифры, пробел, дефис).
   - Функция createCharacter(db, { name }) → Character. Бросает "character_exists", если id=1 уже есть. НЕ принимает статы от клиента — они всегда фиксированные.
   - Функция getCharacter(db) → Character | null.
   - Тип Character экспортируй.

3. РЕПОЗИТОРИЙ (server/db/character-repo.ts):
   - getCharacter, insertCharacter, updateCharacter.
   - Prepared statements. Поле "end" — в кавычках в SQL.

4. REST API (server/api/character.ts):
   - GET /api/character → 200 { character } | 404 { error: "no_character" }.
   - POST /api/character → body { name }.
     * 201 { character }.
     * 400 { error: "invalid_name" }.
     * 409 { error: "character_exists" }.
   - Никаких статов от клиента — только name.
