ЗАДАЧА 4b — инвентарь и экипировка. ТОЛЬКО ЭТО.

1. СХЕМА БД (добавь в server/db/schema.sql, CREATE TABLE IF NOT EXISTS):
   inventory (
     id INTEGER PRIMARY KEY AUTOINCREMENT,
     character_id INTEGER NOT NULL DEFAULT 1 CHECK (character_id = 1),
     item_id TEXT NOT NULL,
     qty INTEGER NOT NULL DEFAULT 1 CHECK (qty >= 1),
     equipped_slot TEXT,                    -- NULL = не надет; иначе "weapon" | "head" | "torso" | "jacket" | "legs" | "boots"
     FOREIGN KEY (character_id) REFERENCES characters(id) ON DELETE CASCADE
   )
   -- Индексы: (character_id), (character_id, equipped_slot), (character_id, item_id)
   -- Один слот — один предмет: UNIQUE(character_id, equipped_slot) WHERE equipped_slot IS NOT NULL
   -- (в SQLite partial unique index: CREATE UNIQUE INDEX ... WHERE equipped_slot IS NOT NULL)

2. РЕПОЗИТОРИЙ (server/db/inventory-repo.ts):
   - getInventory(db) → [{ id, itemId, qty, equippedSlot }]
   - getItemById(db, itemId) — вернуть предмет из gameData.items (не из БД)
   - addItem(db, itemId, qty) — upsert: если такой itemId есть и не надет — qty += qty; если надет или нет — создать новую строку. Учесть: одинаковые предметы в разных слотах — отдельные строки.
   - removeItem(db, inventoryId, qty) — уменьшить qty; если 0 — удалить строку.
   - equipItem(db, inventoryId) — надеть предмет в его слот. Если в слоте уже что-то надето — снять (equipped_slot = NULL). Валидация: слот существует, requirements выполнены (см. ниже). Ошибки: "not_found", "slot_occupied_by_other_character" (нет), "requirements_not_met" (с деталями: {level?: {need, have}, str?: {need, have}, ...}).
   - unequipItem(db, inventoryId) — снять (equipped_slot = NULL).
   - getEquipped(db) → [{ slot, inventoryId, itemId }] — все надетые.
   - canEquip(character, item) → { ok: true } | { ok: false, missing: {level?: {need,have}, str?: {...}, ...} }
     * Проверяет requirements предмета против статов персонажа.
     * Только для type: weapon|armor. Для consumable/ammo/misc — { ok: false, missing: { not_equippable: true } }.

   - Backfill: при старте сервера, если персонаж существует, а inventory пуст — выдать стартовый набор (одноразово). Пометить в meta: key="starter_kit_granted", value="1". Если meta уже есть — пропустить.
   - ВАЖНО: не давать starter_kit повторно (проверять meta).

4. REST API (server/api/inventory.ts — новый файл, регистрируется в index.ts):
   - GET /api/inventory → 200 {
       items: [{ inventoryId, itemId, qty, equippedSlot, item }],  // item — полный объект предмета из gameData
       equipped: { weapon?, head?, torso?, jacket?, legs?, boots? }, // inventoryId + itemId
       capacity: { usedWeight, maxWeight, usedSlots, maxSlots }     // в v2.0 вес не ограничивает, но считаем; maxSlots = 20
     }
     * 404, если персонажа нет.
   - POST /api/inventory/equip → body { inventoryId }
     * 200 { equipped, inventory: [...items] } — обновлённое состояние
     * 400 { error: "not_found" | "not_equippable" | "requirements_not_met", missing? }
     * requirements_not_met: { missing: { level?: {need, have}, str?: {need, have}, ... } }
   - POST /api/inventory/unequip → body { inventoryId }
     * 200 { equipped, inventory }
     * 400 { error: "not_found" | "not_equipped" }
   - Все ответы JSON.
