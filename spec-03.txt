КОНТЕКСТ СЕТТИНГА (не влияет на код, только на тексты):
«Серая Гниль» — биокатастрофа на Урале. Города-оазисы, пустоши, шахты, руины. Тон — постсоветская тоска с чёрным юмором. Игрок стартует в «Заре» (город).

1. СХЕМА БД (добавь в server/db/schema.sql, CREATE TABLE IF NOT EXISTS):
   world_state (
     location_id TEXT PRIMARY KEY,
     respawn_at TEXT NOT NULL,          -- ISO datetime, когда на локации появятся мобы
     last_visited_at TEXT,              -- NULL = ещё не открыта (туман войны)
     updated_at TEXT NOT NULL DEFAULT (datetime('now'))
   )
   -- world_state заполняется лениво: при первом посещении локации создаётся строка.
   -- Для тумана войны: локация "открыта", если есть строка с last_visited_at IS NOT NULL
   -- ИЛИ если она соседняя с уже открытой (открываем соседей при посещении).

2. РЕПОЗИТОРИЙ (server/db/world-repo.ts):
   - getWorldState(db, locationId) → { locationId, respawnAt, lastVisitedAt } | null
   - markVisited(db, locationId) → upsert: last_visited_at = now, обновить updated_at
   - openNeighbors(db, locationId, world) → для каждой соседней локации: если строки нет — создать с last_visited_at = NULL (это «открытая, но не посещённая» — видна на карте, но не активирует спавн)
   - getVisibleLocations(db, world, characterLocationId) → Set<string> id локаций, которые видны на карте:
     * текущая локация — всегда
     * все соседи текущей — всегда
     * все локации, у которых last_visited_at IS NOT NULL — всегда
   - ВАЖНО: world_state не должна содержать «мёртвых» строк для локаций, которых нет в world.json. Если world.json изменился (удалили локацию) — при старте сервера удалить лишние строки (cleanup).

3. ПЕРЕХОДЫ (server/game/world/travel.ts — новый файл):
   - canTravel(world, character, targetId) → { ok: true } | { ok: false, error: 'not_adjacent' | 'no_connection' | 'unknown_location' }
     * targetId существует в world.json
     * между location_id и targetId есть связь в connections (двусторонняя — проверить обе стороны)
   - getTravelOptions(world, character, targetId) → { distance, baseTimeMs, type: 'plain' | 'road', canQuick: boolean }
     * baseTimeMs: 1500ms (plain) / 900ms (road) — короткие переходы из M19.
     * canQuick: true, если у targetId уже есть last_visited_at IS NOT NULL.
   - ВАЖНО: encounters и «путь в 3–10 секунд» — это этап 7. На этапе 3 переход МГНОВЕННЫЙ: POST → обновить location_id → вернуть новое состояние. baseTimeMs — только для клиентской анимации (прогресс-бар «В пути…»), не блокирует сервер.

4. REST API (server/api/world.ts — новый файл, регистрируется в index.ts):
   - GET /api/world → { locations: [...], visible: [...], current: locationId }
     * locations: все локации из world.json в виде { id, type, nameKey, coords, dangerLevel, levelRange, connections: [{to, type}], isVisible: boolean, isVisited: boolean }
     * НЕ отдавать descriptionKey, ambientKeys, art, spawnTable — это этап «экран локации» отдаст по конкретной локации.
     * visible: массив id
     * current: текущая локация персонажа
   - GET /api/location/:id → { id, type, nameKey, descriptionKey, ambientKeys, coords, dangerLevel, levelRange, connections, isCurrent: boolean, isVisited: boolean }
     * 404, если локации нет в world.json
     * 403, если локация не видима (не в visible)
     * ambients: сервер выбирает 2–3 случайные фразы из ambientKeys и отдаёт как { ambientKeys: [...] } — клиент сам переводит через i18n
   - POST /api/travel → body { to: locationId }
     * 400 { error: 'not_adjacent' | 'no_connection' | 'unknown_location' | 'no_character' }
     * 200 { character, fromLocationId, toLocationId }
     * Обновляет characters.location_id, markVisited(toLocationId), openNeighbors(toLocationId, world)
     * Валидация: character существует
     * НЕ запускает encounter (этап 7)
   - Все ответы — JSON, Content-Type application/json.
