ZOD-СХЕМЫ (используй эти определения, не выдумывай свои):
- I18nKey: /^[a-z0-9_]+(\.[a-z0-9_]+)+$/ — например "location.zarya.name"
- IdSchema: /^[a-z0-9_]+$/
- HexColor: /^#[0-9a-fA-F]{6}$/
- ItemSchema: discriminatedUnion по полю type: "weapon" | "armor" | "consumable" | "ammo" | "misc".
  Общие поля: id, nameKey, descriptionKey, icon (1–4 символа), price (int >=1), weight (>=0), rarity (enum), requirements (object), durability (int >=1, default 100), tags (string[]).
  weapon: + slot:"weapon", weaponType (enum melee|light|medium|heavy|thrown|energy), damage {min,max}, accuracy (0-100), speed (0.1-5), charges?, ammoType? (если charges — обязателен ammoType).
  armor: + slot (head|torso|jacket|legs|boots), armor {head,torso,arms,legs} (int >=0).
  consumable: + effect {heal?, cure? (poison|bleed|stun), restoreCharges?, durationRounds?}.
  ammo: + ammoType, charges (int >=1).
  misc: без доп. полей.
- ItemsFileSchema: { version: string, items: Item[] } + superRefine на дубликаты id + проверка, что для каждого weapon.ammoType есть ammo-предмет этого типа.
- MobSchema: id, nameKey, descriptionKey?, level (1-50), hp (>=1), stats {str,agi,int,end} (1-50), attack {min, max, accuracy 0-100, zoneWeights {head,torso,arms,legs} — сумма 100}, ai (aggressive|coward|tactical|berserk), xp (>=0), loot { guaranteed?: LootEntry, rare: LootEntry[] }, spawnLevelRange [min,max], elite? {hpMult, dmgMult, xpMult, rareChanceBonus}, tags[].
- LocationSchema: id, type (city|waste|ruins|mine|road|camp), nameKey, descriptionKey, ambientKeys[] (1-10), coords {x:0-19, y:0-19}, dangerLevel (0-100), levelRange [min,max], connections [{to, type: plain|road}] (>=1), spawnTable [{mobId, weight, min, max}] (default []), cover (default false), anomaly? (spore_low|rot_low), art { sky:[Hex,Hex], ground:Hex, silhouettes:[{type, x:0-1, y:0-1, scale:0.1-3, color:Hex, flip?}], weather?, fog? }, shopId?, npcIds[] (default []).
- WorldFileSchema: { version, size:{width,height} (1-50), startLocationId, locations: Location[] (>=1) } + superRefine:
  * дубликаты location.id,
  * coords в пределах size,
  * нет двух локаций на одних coords,
  * все connections указывают на существующие id,
  * связи двусторонние (если A→B, то B→A),
  * связи только по соседству (|dx|<=1 и |dy|<=1),
  * startLocationId существует.
- BattlePhrasesFileSchema: { version, categories: Record<string, {minVariants:1-20, placeholders: string[]}> }, ключи категорий — /^battle\.[a-z0-9_.]+$/.
- I18nFileSchema: Record<I18nKey, string(min 1)>.

i18n API:
- loadI18n(dataDir) → { ru: Record<string,string>, en: Record<string,string> }, при старте проверяет, что наборы ключей совпадают (иначе throw).
- t(key, lang, params?) → строка с подстановкой {k}=v из params; если ключа нет — вернуть `[missing:${key}]` и записать warning в лог.
- На клиенте: js/i18n.js хранит текущий язык, setLang(lang) перезагружает словарь через /api/i18n/:lang, обновляет все элементы с data-i18n="key" и data-i18n-placeholder.
- Все элементы с текстом в HTML имеют data-i18n. Хардкод строк в HTML запрещён (кроме <title> — но и его подставь через JS).
